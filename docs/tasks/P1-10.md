# P1-10: Approved schedules and configurable utility decisions

**Role:** Agents (NPC behaviour)
**Branch:** task/P1-10-schedules-decisions
**Depends on:** P1-09 (merged)

## Goal
Load approved workday/Restday schedules and let NPCs choose a current intention
from schedule fit and needs through explicit, caller-supplied utility tuning.

## Context
Read AGENTS.md and required startup documents, ARCHITECTURE sections 3 and 5,
docs/design/WORLD.md/CHARACTERS.md, and Content/npcs/npcs.json. Game day 1 is the
approved Thirdday; the seven-day order ends with Restday. This task chooses an
intention only; Actions/travel/economy systems perform it later.

## You may edit
- Packages/com.geltrax.livingworld.simulation/Runtime/Agents/
- SimulationTests/Agents/

## You must not edit
- Anything outside those folders. No Economy/Knowledge coupling, Content/docs,
  configuration, dependencies, Unity, git writes or child agents.

## Requirements
1. C# 9/.NET Standard 2.1, tests first, no Unity/dependencies.
2. Extend the existing production NPC loader/definitions with immutable workday
   and Restday schedules from approved JSON. Parse strict HH:mm integer minutes;
   support overnight entries; validate activity/location, positive duration,
   overlaps, duplicate/missing schedule sections and unknown locations. Preserve
   all 20 real schedules and deterministic order. Unknown future top-level fields
   remain ignored.
3. Represent approved activities without erasing distinctions (eat, sleep, work,
   socialize, shop, rest, chores, pray). Schedule lookup uses Thirdday as Day 1,
   Restday every seventh world day in the approved calendar, and returns no entry
   for genuine schedule gaps. Do not insert travel blocks yet.
4. Add explicit current Activity/Intention to NpcState: kind, destination and
   chosen-at time. Keep schedule state separate from the decision system.
5. Implement simple deterministic utility scoring for at least Eat, Sleep, Work,
   Shop and Socialize. Inputs are schedule fit, Hunger, Energy, Social, and a
   read-only context snapshot containing available copper/shop availability.
   The Agents assembly must not reference Economy or world truth/Knowledge.
6. All thresholds/weights and tie behavior come from a validated DecisionTuning
   object supplied to DecisionSystem; there are no production defaults because
   approved data does not specify them. Test-only values are fixtures, not game
   balance. Ties use WorldState.Rng over candidates in stable enum/order.
7. DecisionSystem is phase Decisions and iterates NPCs in registry order. A
   sleeping scheduled NPC chooses Sleep; a sufficiently hungry NPC with supplied
   money/shop context can choose Shop; urgent needs may override schedule when
   the supplied tuning says so. No item purchase, movement or need recovery.
8. Keep natural schedule-loading and decision-state groups independently below
   ~500 lines; report a safe PR split if the combined task exceeds the limit.

## Tests required
- Load all approved schedules; assert Mira workday/night and Restday entries,
  Thirdday/Restday mapping, overnight lookup and a real gap.
- Reject malformed/missing/overlapping schedules and unknown locations.
- Hungry NPC with money/shop available chooses Shop under explicit test tuning;
  without funds/availability it does not. Night schedule chooses Sleep.
- Urgent need override, stable ties using seeded RNG, reversed registration gives
  identical per-NPC results, and Decisions phase is correct.
- Full Debug/Release suites and `git diff --check`.

- [ ] All existing tests pass in Debug and Release

- [ ] Orchestrator reviews, records missing tuning and checks CI

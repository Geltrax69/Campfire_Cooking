# P1-18a: Reputation truth contracts

**Role:** Core Simulation
**Branch:** task/P1-18a-reputation-events
**Depends on:** P1-03

## Goal
Add a strongly typed reputation-group ID and optional reputation-change facts to
world events so P1-18 can change group standing without hiding state transitions.

## Context
Reputation is game state and every change must be world truth. Existing event fields
cannot identify a group or represent a signed standing delta.

- `SimulationTests/Core/Events/`

## Requirements
1. Add `ReputationGroupId` with the same validation, ordinal comparison and stable hashing semantics as other content IDs.
2. Append `ReputationChanged` after all existing `WorldEventType` numeric values.
3. Add optional `ReputationGroupId` and signed nonzero reputation delta facts to `WorldEvent`/`EventLog.Append` without breaking existing callers.
4. Require both reputation fields for `ReputationChanged` and reject those fields on other event kinds.
5. Failed validation must leave event count, next ID and last time unchanged.
6. Do not add Knowledge rules, thresholds, content values or Unity references.

## Tests required
- ID equality/order/hash/default behavior.
- Valid positive and negative reputation changes round-trip through EventLog.
- Missing/zero/out-of-range or misplaced reputation facts fail atomically.
- Existing event numeric values remain stable.

# P5-02: Growth and decline

**Role:** Agents (NPC behaviour) agent
**Branch:** task/P5-02-growth-decline
**Depends on:** P5-01

## Goal
Implement village growth and decline through conditions (never upgrade buttons): in-migration, out-migration, and the decline spiral.

## Context
Phase 5 is "Town development". P5-01 built the town stats. This task implements section 2 of docs/design/TOWN.md: the village grows or shrinks because conditions change.

## You may edit
- Packages/com.geltrax.livingworld.simulation/Runtime/Agents/ (migration systems)
- SimulationTests/Agents/ (new test files)

## You must not edit
- Anything outside the folders above. Content/ is approved.

## Requirements
1. **In-migration** (seasonal check):
   - Conditions: happiness ≥ 65 AND employment ≥ 80 AND foodSupply ≥ 50 AND housing ≥ 70.
   - If met: one household arrives per season (3-5 people). They are background villagers (not simulated NPCs); population stat increases.
   - Record a truth event (HouseholdArrived).
   - At most one per season.
2. **Out-migration** (spring check, per-NPC):
   - For each NPC aged 15-25: if ambition ≥ 70 AND (employment prospects low OR family tension), they may leave for King's Rest.
   - Use seeded RNG for the decision (not guaranteed).
   - If they leave: remove from NPC registry (or mark as departed), population decreases, household happiness dips (record event).
   - Never forced; resolved through normal rules.
3. **Decline spiral** (emergent, not hardcoded):
   - The stat formulas already create the spiral: foodSupply < 20 in winter → hunger rises → happiness falls → out-migration conditions met → population falls.
   - Do NOT add explicit spiral rules. The task is to verify the spiral CAN happen through the existing systems.
   - Add a test that demonstrates the spiral: set food supply very low, run through winter, verify happiness falls.
4. **Village → town thresholds** (documented, not implemented):
   - The design states thresholds (population ≥ 500, etc.) but says they're "unreachable in the prototype".
   - Do NOT implement the town transition. Just document in code that the thresholds exist for later phases.
5. **Deterministic**: Use seeded RNG for migration decisions.

## Tests required
- `HighStatsTriggerInMigration`: Set all stats high; run a season; verify population increases by 3-5.
- `LowStatsPreventInMigration`: Set food supply low; run a season; verify no in-migration.
- `AmbitiousYouthMayLeave`: Create a 20-year-old with high ambition and low employment; run spring; verify they may leave (use a seed that triggers it, or run many trials).
- `DeclineSpiralEmerges`: Set food supply to 10 in winter; run 30 days; verify happiness decreased.

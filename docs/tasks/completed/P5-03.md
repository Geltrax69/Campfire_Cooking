# P5-03: Emergent events

**Role:** Agents + Economy agent
**Branch:** task/P5-03-emergent-events
**Depends on:** P5-01

## Goal
Implement 10 emergent events that fire ONLY when world conditions are met (never scripted, never on a timer except the calendar). Each event can chain into others.

## Context
Phase 5 is "Town development". P5-01 built town stats. This task implements section 3 of docs/design/TOWN.md: events that emerge from the world's state.

## Requirements
1. **Event definitions**: 10 events from TOWN.md section 3:
   - `event_food_shortage`: food_supply < 25 AND season == winter → rationing, bread price cap, NPCs skip meals, happiness -10/month
   - `event_wolf_attack`: season == winter AND livestock > 0 AND (daysSinceSnow > 20 OR scarcity) → wolves take 1-3 livestock, safety -15, bounty claimable
   - `event_festival`: calendar date (Harvest Feast, Thawday) → happiness +, trade +
   - `event_fire`: (random low chance, or lightning) → building damage, infrastructure -
   - `event_theft_wave`: crime > 5/month → safety -, trade -
   - `event_merchant_arrival`: seasonal (not winter) → trade +, new goods
   - `event_fever`: (follows food shortage or random) → health -, happiness -
   - `event_drought`: daysSinceRain > 30 AND season == summer → food_supply -, trade -
   - `event_wheel_failure`: wheelCondition < 20 → infrastructure -, food_supply - (no mill → no flour)
   - `event_bridge_project`: communityFund > 5000 AND season != winter → infrastructure +, employment +
2. **EmergentEventSystem** (IWorldSystem): Checks conditions daily (or weekly). If conditions met and event not already active, fire it.
   - Events are NOT on a timer. They fire when conditions are met.
   - Each event has a duration (e.g., food shortage lasts until food_supply >= 25).
   - Record truth events when firing and when ending.
3. **Chaining**: Events can trigger other events.
   - Food shortage → fever (weakened villagers) → theft wave (desperate).
   - Wolf attack → merchant arrival dips (travelers hear).
   - Implement as: when an event fires, it may set conditions that make another event's conditions true.
   - Do NOT hardcode "if food shortage then fever"; instead, food shortage lowers health, which makes fever's conditions (low health + winter) true.
4. **Player can influence**: The player can move stats through actions (e.g., donating to community fund enables bridge project; hunting wolves reduces attacks).
   - Do NOT add player-specific event logic. The events read world state; player actions change world state.
5. **Deterministic**: Condition checks are deterministic. If RNG is needed (e.g., fire chance), use seeded RNG.

## Tests required
- `FoodShortageFiresInWinter`: Set food_supply=20, season=winter; run; verify food shortage event fires.
- `WolfAttackFiresInWinter`: Set season=winter, livestock>0, daysSinceSnow=25; verify wolf attack fires.
- `EventsChain`: Trigger food shortage; verify fever conditions become true (or fever fires).
- `MerchantArrivalSeasonal`: Verify merchant does not arrive in winter.
- `EventEndsWhenConditionsClear`: Food shortage active; raise food_supply to 30; verify event ends.

# P3-04: Phase 3 acceptance (week-long cooking simulation)

**Role:** Test & Scenario agent
**Branch:** task/P3-04-acceptance
**Depends on:** P3-01, P3-02, P3-03

## Goal
Prove Phase 3 works end-to-end: a 7-day village simulation where NPCs cook daily meals, the player practices cooking, skills improve, and the effects (happiness, tavern popularity, demand, prices) are visible. Wire Phase 3 state into save/load persistence.

## Context
Phase 3 is "Skills, crafting and cooking". P3-01 built skill state. P3-02 built recipe execution. P3-03 built cooking effects. This task:
1. Wires all Phase 3 mutable state into the Persistence save/load (format version 3, or extend version 2)
2. Runs a 7-day acceptance simulation proving the systems work together
3. Produces a readable log

## Requirements
1. **Persistence wiring**: Extend the save format to include:
   - `SkillStore` for player and all NPCs (use the Capture()/Restore() APIs from P3-01)
   - `NpcState.Happiness` (RestoreHappiness API from P3-03)
   - `TavernPopularityState` (Restore API from P3-03)
   - `IngredientDemandState` (Restore API from P3-03)
   - Bump format version (2 → 3) and ensure v2 documents still load with Phase 3 defaults.
2. **7-day acceptance scenario** (`SimulationTests/Scenarios/Phase3CookingAcceptanceTests.cs`):
   - Set up: village with Bessa (tavern, cooking level 3), player (cooking level 1), ingredients available.
   - Day 1-7: Each day, Bessa cooks 2 meals (campfire stew), player practices cooking 1 meal.
   - Verify: 
     - Player skill points accrue (7 points after 7 days, or 14 if taught by Bessa)
     - Bessa's cooking raises tavern popularity
     - NPCs who eat Bessa's meals gain happiness
     - Ingredient demand for fish/firewood rises
     - No exceptions, no negative inventories, money conserved
   - The test must be deterministic (fixed seed).
3. **Readable log**: The acceptance test writes a human-readable log to `SimulationTests/Scenarios/Phase3_Acceptance_Log.md` (or as test output) showing:
   - Day-by-day: who cooked what, quality, who ate, happiness changes
   - Final: player skill level/points, tavern popularity, ingredient demand levels
   - This log is the "proof" the user can read.
4. **Save/load round-trip**: In the acceptance test, save at day 4, load, continue to day 7. Verify the final state matches an uninterrupted 7-day run (determinism).

## Tests required
- `SevenDayCookingAcceptance`: The full scenario above, with assertions on skill points, happiness, popularity, demand.
- `Phase3StateSaveLoadRoundTrip`: Save/load preserves skill stores, happiness, popularity, demand.
- `Phase3SaveFormatVersion`: Version 3 saves load; version 2 saves load with Phase 3 defaults.

# P1-21a: Core restore contracts

**Status:** Completed

**Role:** Core Simulation
**Branch:** task/P1-21a-core-restore
**Depends on:** P1-20

## Goal
Expose small, validated Core snapshots so Persistence can restore event-log identity
and queued-command timing exactly without reflection or private-field access.

## Context
P1-21 must continue deterministically after save/load. Re-appending retained events
cannot preserve event IDs after pruning, and pending FIFO eligibility is hidden today.

## You may edit
- `Packages/com.geltrax.livingworld.simulation/Runtime/Core/`
- `SimulationTests/Core/`

## You must not edit
- Anything outside the folders above. Report needed changes elsewhere.

## Requirements
1. Add an immutable EventLog state view containing retained events plus the issued-ID
   and timestamp high-water marks, including when every old event was pruned.
2. Add validated capture/restore construction that preserves event records exactly and
   makes the next append use the same ID/time rules as before saving.
3. Add an immutable ordered pending-command view containing the command reference and
   eligible minute, plus validated restore support for Persistence to rehydrate decoded
   commands without changing FIFO order or next-minute eligibility.
4. Keep APIs minimal and assembly-internal where only Persistence needs them. Do not
   serialize JSON here or add command-type knowledge to Core.
5. Preserve existing mutation guards and deterministic order.

## Tests required
- Pruned/empty EventLog round trip preserves high-water state and next appended ID.
- Pending commands round trip preserves FIFO order and exact eligible minutes.
- Invalid snapshots are rejected atomically.

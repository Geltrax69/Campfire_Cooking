# P5-04: Phase 5 acceptance (year-long town simulation)

**Role:** Test & Scenario agent
**Branch:** task/P5-04-acceptance
**Depends on:** P5-01, P5-02, P5-03

## Goal
Prove Phase 5 works end-to-end: a year-long simulation where town stats move with seasons, emergent events fire, growth/decline happens, and all state survives save/load.

## Context
Phase 5 is "Town development and emergent events". P5-01 built town stats. P5-02 built growth/decline. P5-03 built emergent events. This task:
1. Wires town state (TownStatsState, MigrationState, EmergentEventState) into save/load persistence (format v5, or extend v4)
2. Runs a year-long acceptance simulation proving the systems work together
3. Produces a readable log

## Requirements
1. **Persistence wiring**: Extend the save format to include:
   - `TownStatsState` (11 stats + last computed month)
   - `MigrationState` (in/out migration counts, last check dates)
   - `EmergentEventState` (active events + start days, LastMerchantDay)
   - Use the `Capture()`/`Restore()` APIs from P5-01, P5-02, P5-03.
   - Bump format version (4 → 5) and ensure v4/v3/v2/v1 documents still load with town defaults.
2. **Event types** (from P5-03 open question): If the orchestrator hasn't added them, add `WorldEventType.EmergentEventFired` and `WorldEventType.EmergentEventEnded` to Core (one line each, P3-03 precedent). Update EmergentEventSystem to emit them.
3. **Year-long acceptance scenario** (`SimulationTests/Scenarios/Phase5TownAcceptanceTests.cs`):
   - Set up: village with initial state (from previous phases).
   - Simulate 365 days (full year, autumn → summer → autumn):
     - Each day: run all town systems (stats monthly, migration seasonal, events daily).
     - Track: population, food supply, safety, happiness over time.
     - Verify at least 2 emergent events fire during the year (e.g., merchant arrival in spring, wolf attack in winter).
   - Verify:
     - Stats change over the year (not static).
     - Events fire when conditions are met.
     - No exceptions, stats stay within 0-100 (or valid ranges).
   - The test must be deterministic (fixed seed).
4. **Readable log**: The acceptance test writes a human-readable log to `SimulationTests/Scenarios/Phase5_Acceptance_Log.md` showing:
   - Month-by-month: key stats (population, food, safety, happiness, trade).
   - Events: when they fired, when they ended.
   - Migration: households arrived/departed.
   - Final: stats, population change.
5. **Save/load round-trip**: Save at day 180, load, continue to day 365. Verify the final state matches an uninterrupted 365-day run (determinism).

## Tests required
- `YearLongTownAcceptance`: The full scenario above.
- `TownStateSaveLoadRoundTrip`: Save/load preserves town stats, migration, events.
- `TownSaveFormatVersion`: Version 5 saves load; version 4 saves load with town defaults.

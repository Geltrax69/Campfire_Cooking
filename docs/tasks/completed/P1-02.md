# P1-02: World state and fixed-order ticks

**Role:** Core Simulation
**Branch:** task/P1-02-world-ticks
**Depends on:** P1-01 (merged in PR #1)

## Goal
An engine-independent world advances one game minute per tick and invokes
registered systems in a deterministic order, independent of registration order.

## Context
Read AGENTS.md, its required documents, and ARCHITECTURE sections 2–3.
P1-01 exposes GameTime(long), Advance(long), SimRng(ulong) and typed content IDs.

## Requirements
1. Tests first, C# 9, namespace LivingWorld.Simulation.Core, no Unity.
2. A sealed partial WorldState has Clock (GameTime, internal setter), Rng
   (SimRng, get-only) and constructor WorldState(ulong seed, GameTime startTime = default).
   Partial allows later Core tasks to add owned state without editing this file.
3. IWorldSystem exposes string Id, SimulationPhase Phase and void Tick(WorldState state).
   SimulationPhase: Commands, Needs, Decisions, Actions, Perception, Social, Economy,
   Memory in that order. Time advances centrally before Commands.
4. World(WorldState state), State get-only, RegisterSystem(IWorldSystem), Tick().
   Order by phase then ordinal Id; reject nulls, empty/whitespace or duplicate IDs
   and unknown phases. Freeze captured registration keys so mutable properties
   cannot reorder systems silently. Registration closes at the first Tick.
5. Advance the clock exactly once BEFORE any systems. Reject reentrant ticks and
   registration from a running tick. Empty world supports 1440 ticks = day 2.
6. If a system throws, stop the tick, propagate the exception and mark the World
   IsFaulted; later Tick calls must refuse to continue a partially applied tick.
   This is fail-stop, not transactional rollback. Guard clock overflow before
   any system runs. Do not invent game rules or implement future systems.
7. Aim below 400 lines including tests; avoid per-tick sorting/allocations.

## Tests required
- Empty world advances 1440 minutes; nonzero start time respected.
- Scrambled registration gives all phases in prescribed order and ordinal
  same-phase order; systems see the advanced clock and same state/RNG instance.
- Invalid/duplicate registration; mutable keys cannot reorder after registration.
- Reentrant tick, registration during tick, fail-stop after exception and overflow.
- Same seed/input produces identical traces and RNG state across many ticks.

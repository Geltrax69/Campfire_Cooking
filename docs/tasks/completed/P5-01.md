# P5-01: Town stats

**Role:** Agents + Economy agent
**Branch:** task/P5-01-town-stats
**Depends on:** P4-04

## Goal
Implement 11 town stats computed from world state (never set by hand, never scripted). Each stat has a formula the simulation computes monthly.

## Context
Phase 5 is "Town development and emergent events". This task builds the stats foundation from docs/design/TOWN.md section 1. P5-02 will add growth/decline. P5-03 will add emergent events that read these stats.

## Requirements
1. **TownStats class**: 11 stats, each 0-100 unless noted:
   - `Population` (count): living simulated NPCs + 100 background villagers
   - `Wealth` (copper count): sum of NPC money + village fund + granary stock at base price + shop stocks at base price
   - `FoodSupply` (0-100): days of village food in storage ÷ 180 × 100, capped at 100
   - `Safety` (0-100): 100 − (wolf incidents this winter × 15) − (unresolved crimes × 5) + (night watch ? 10 : 0) + palisade bonus
   - `Housing` (0-100): sound roofs ÷ households needing them × 100
   - `Employment` (0-100): working-age NPCs with productive work ÷ working-age NPCs × 100
   - `Trade` (0-100): this month's traveler + merchant copper ÷ 1700 × 100
   - `Happiness` (0-100): average over NPCs of (social need met × 0.4 + food security × 0.3 + recent festival × 0.2 − fear events × 0.1)
   - `Crime` (incidents/month count): theft + burglary + vandalism events in last 30 days
   - `Infrastructure` (0-100): wheel condition × 0.4 + palisade × 0.25 + well & roads × 0.2 + granary building × 0.15
   - `Reputation` (0-100): (apple fame + road safety + hospitality) ÷ 3, moved by traveler experiences
2. **TownStatsSystem** (IWorldSystem): Recomputes all stats monthly (on the 1st of each month, or every 30 days).
   - Stats are stored in WorldState (new section) with Capture()/Restore() for persistence.
   - The system reads ONLY world state (inventories, NPCs, events, etc.), never beliefs.
3. **Starting values**: Use the design's starting values as the initial computation (the formulas should produce approximately these from the initial world state; document any discrepancies).
4. **Stat interactions** (emergent, not hardcoded):
   - The formulas naturally create interactions (e.g., low food supply → computed happiness is lower because food security is low).
   - Do NOT add explicit "if food low then happiness -10" rules; the formulas handle it.
5. **Deterministic**: Monthly recomputation uses only world state, no RNG.

## Tests required
- `StatsComputeFromWorldState`: Build a small world; verify population = NPCs + 100, wealth = sum of money, etc.
- `FoodSupplyReflectsGranary`: Add/remove granary stock; food supply changes accordingly.
- `SafetyReflectsWolfIncidents`: Record wolf incidents; safety decreases.
- `CrimeCountsRecentEvents`: Record theft events; crime stat reflects last 30 days only.
- `StatsAreMonthly`: Stats don't change mid-month; recompute on month boundary.

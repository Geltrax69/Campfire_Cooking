# P1-20a: Deterministic Apple Test scenario harness

**Status:** Completed

**Role:** Test & Scenario
**Branch:** task/P1-20a-apple-harness
**Depends on:** P1-08–P1-19

## Goal
Build a reusable test-only village harness that runs the approved three-day Apple
Test minute by minute through the real simulation systems and exposes its outcomes.

## Context
The scenario itself supplies the approved starting setup and player theft command.
Shortages, beliefs, rumors, restocking, price movement and guard response must come
from the existing general systems, not from hard-coded outcome flags.

## You may edit
- `SimulationTests/Scenarios/`
- `SimulationTests/Tools/`

## You must not edit
- Runtime code, Content, or anything outside the folders above. Report missing APIs.

## Requirements
1. Construct a tiny fixed-seed world with Mira/shop, farmer, witness, rumor contacts,
   guard and configured buyers using approved Apple Test values: 20 start stock,
   3-copper retail, six stolen at Day 1 14:00, dusk count, low-stock threshold 10,
   45-item wholesale delivery at 1 copper and bounded rise to 4.
2. Enqueue the player theft through `CommandSystem`; do not mutate theft inventory directly.
3. Drive buyer attempts from immutable buyer schedules/needs through a general test-only
   action system, producing real full/partial/failed purchases rather than preset outcomes.
4. Register real Perception, production, restock, price and memory systems in phase order.
5. Use a 50% seeded witness chance and expose whether the witness actually formed a belief.
6. At configured meetings, use real `RumorExchange`; if no speaker belief exists, no rumor appears.
7. Use real stock inference at dusk and real guard suspicion evaluation at the end.
8. Run through Day 3 with caller-owned/restorable subsystem state and expose a result snapshot
   plus deterministic world-truth report. No exact rumor mutation rule is required here; use
   a zero-mutation scenario setting while P1-15 separately proves seeded distortion.
9. Avoid outcome-specific writes such as directly setting a missing-stock belief, price,
   guard result, rumor, delivery or failed purchase.

## Tests required

- Starting item/copper totals and deterministic configuration are validated.
- Same seed produces byte-identical report and result snapshot.

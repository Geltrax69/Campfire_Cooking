# P1-18b: Evidence threshold and group reputation

**Role:** Knowledge
**Branch:** task/P1-18b-suspicion-reputation
**Depends on:** P1-15, P1-18a

## Goal
Evaluate a guard's own beliefs through explicit evidence rules and maintain bounded,
event-logged player standing for strongly typed reputation groups.

## Context
The Apple Test guard may watch or inquire below the proof threshold, but must not
treat the player as a proven thief until approved evidence reaches 70.

## Requirements
1. Add caller-owned, deterministically ordered group reputation state with values bounded 0–100.
2. Applying a requested reputation adjustment clamps the final value, logs the actual nonzero
   applied delta as `ReputationChanged`, and logs nothing when already at a bound.
3. Add an immutable suspicion result with total evidence, explicit proof threshold and `MayAct`.
4. Evaluate only the named guard's belief store; never query world events, another NPC's beliefs or hidden truth.
5. Use caller-supplied evidence policy/rules because approved weights depend on witness/source context;
   preserve stable belief ordering and reject invalid scores/thresholds.
6. A count-derived missing-stock belief cannot identify the player unless a separate guard belief does.
7. Keep state separate from logic and suitable for later persistence.

## Tests required
- Evidence 69 means no action; 70 means action.
- A rumor plus stock-missing evidence below 70 does not authorize accusation.
- Direct own evidence above threshold does; evidence held only by another NPC does not.
- Reputation adjusts independently by group, clamps at 0/100, and logs actual deltas.
- Reconstructed reputation state yields identical values and deterministic order.

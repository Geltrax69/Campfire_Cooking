# P1-04: Next-tick FIFO commands

**Role:** Core Simulation
**Branch:** task/P1-04-command-queue
**Depends on:** P1-02, merged in PR #2

## Goal
Player and NPC commands submitted at minute N execute no earlier than minute
N+1, in enqueue order, during the Commands phase before needs and decisions.

## Context
Read AGENTS.md and required documents; ARCHITECTURE sections 3 and 11.
World advances Clock before running systems. IWorldSystem has Id, Phase and
Tick(WorldState). WorldState is sealed partial; GameTime.Advance checks overflow.

## Requirements
1. C# 9, tests first, no engine dependencies; target <=350 lines with tests.
2. IWorldCommand.Execute(WorldState state) is the command interface. Document
   commands as simulation-only, immutable input descriptions (test helpers may
   record output externally). Do not implement game-specific commands yet.
3. Add partial WorldState.EnqueueCommand(IWorldCommand) and PendingCommandCount.
   Capture eligible minute as Clock.Advance(1) at enqueue, checked before mutation.
   Enqueue rejects null; no state changes occur until processed.
4. CommandSystem : IWorldSystem, Id = core.commands, Phase = Commands, processes
   eligible commands in FIFO order. Register it explicitly during world setup;
   do not modify World's constructor. Add a clear setup example to your report.
5. Commands enqueued within ANY system/command at minute N wait until N+1,
   even if enqueued by another Commands-phase system ordered before core.commands.
   Do not merely snapshot queue length at CommandSystem.Tick.
6. Remove a command before calling Execute; exceptions propagate to World's
   fail-stop mechanism. Never automatically retry a partially executed command.
   Keep remaining pending commands intact. Reject processing reentrancy.
7. No cross-world queue state, wall clock or unordered processing. Future
   persistence will serialize concrete command data, not arbitrary delegates.

## Tests required
- No immediate execution; next tick FIFO; commands before Needs and Decisions.
- Enqueue during commands, earlier Commands-phase system and later phases defers.
- No repeats across empty ticks; queues isolated; null and minute-overflow atomicity.
- Command failure stops later execution, faults world and does not retry.
- Reentrant processing rejected; seeded command traces repeat deterministically.

# P2-12: Persist Phase 2 state (extend saver/loader/schema; determinism)

**Role:** Persistence
**Branch:** task/P2-12-persist
**Depends on:** P2-01 … P2-11b

## Goal
Every Phase 2 system survives a save/load cycle: extend the versioned JSON
save format to cover all new mutable state, and re-prove determinism.

## Context
P1-21e/f built the versioned JSON saver/loader and proved
run(1000) == save→load→run(1000) byte-identical. Phase 2 added new
WorldState-owned progress in every task — each with an internal
Capture/Restore convention waiting for this task to wire it up. Until now,
a reloaded world loses: relationship values, baselines, dynamics cursors,
attributed-memory ledgers, smithy progress, merchant/traveler/bounty/fund/
harvest schedules, tax/community/prosperity state, debt ledgers, and
inventory lot ages (spoilage).

## You may edit
- `Packages/com.geltrax.livingworld.simulation/Runtime/Persistence/`
- `SimulationTests/Persistence/`

## You must not edit
- Anything else. If a state's Capture/Restore API is missing or
  insufficient, report it — do not edit other folders.

## Requirements
1. **Survey**: enumerate every WorldState-owned Phase 2 state (grep the
   `Restore*` methods and `*State` properties added in P2-01…P2-11b) and
   list it in the final report with its save-section name. Nothing may be
   missed.
2. **Saver**: add one `Write*` section per state, following the existing
   `WriteWorld` pattern. Extend inventory serialization (shops, belongings)
   with per-lot ages so spoilage survives. Bump `formatVersion` (1 → 2)
   and document every new section in `SCHEMA.md`.
3. **Loader**: mirror readers for every new section, calling the existing
   internal `Restore*` methods. Loader must reject unknown future versions
   and validate restored values the same way the constructors do.
4. **Backwards compatibility**: decide and document — does the v2 loader
   still read v1 files (missing sections → defaults), or is v1 rejected?
   Pick one, document it in SCHEMA.md, test it.
5. **Determinism proof**: (a) the P1-21f proof still passes unchanged;
   (b) NEW: full-village proof — assemble the village (P2-11a's
   `VillageAssembly`), run 400 ticks, save, load, run 600 more, and prove
   the final world digest equals an uninterrupted 1000-tick run AND that
   save→load→save produces byte-identical documents.

## Tests required
- Round-trip: every new section survives save→load with values intact
  (one test per section or grouped — your choice, keep it readable).
- save→load→save byte-identical on the full village.
- The 400/600 village determinism proof.
- P1-21f's original proof still green.
- v1/v2 compatibility per the documented decision.
- Full suite green, Debug + Release.

# P1-03: World events and append-only event log

**Role:** Core Simulation
**Branch:** task/P1-03-world-events
**Depends on:** P1-02, merged in PR #2

## Goal
Store immutable world truth with deterministic IDs, filtered queries and safe
pruning. This is not NPC knowledge; no perception or accusation rules yet.

## Context
Read AGENTS.md and its required documents; ARCHITECTURE sections 4 and 6.
Existing namespace LivingWorld.Simulation.Core contains GameTime, NpcId,
LocationId, ItemTypeId and a sealed partial WorldState.

## Requirements
1. Tests first, C# 9, no engine dependencies. Keep implementation plus tests
   near 400 lines; do not trade clarity for line count.
2. Immutable WorldEvent with WorldEventId (positive long, 0 invalid), GameTime
   Time, LocationId Location, WorldEventType Type, ActorId? Actor, immutable
   Targets, Visibility, and optional typed ItemTypeId/quantity/copper details.
   ActorId distinguishes player from NPC without pretending the player is an NPC.
3. Types cover Purchase, PartialPurchase, FailedPurchase, Theft, StockCounted,
   Conversation, Departure, Arrival. Visibility: Hidden, Quiet, Normal, Loud.
   Do not add inference or story-specific fields/rules. Reject invalid IDs,
   enum values, negative quantities/copper and malformed actor values.
4. EventLog.Append returns the new event; IDs are monotonic, never reused after
   pruning. Validate before changing state. Time cannot go backwards, even after
   pruning every event. Events at the same minute retain append order.
5. Query supports inclusive time bounds and optional location/type; results
   remain ordered by event ID and cannot mutate log storage or event collections.
6. PruneBefore(cutoff, retainedIds) removes older events except explicitly
   retained references from future beliefs/memories; equality at cutoff stays.
   Enumerate/validate retention input before mutation. No automatic pruning yet.
7. Add WorldState.Events via a partial class in your own folder, initialized per
   state. Never edit Ticking/WorldState.cs. Runtime consumes no JSON libraries.

## Tests required
- Sequential IDs/time ordering, stable equal-time order, query filters/boundaries.
- Immutability/defensive copies, invalid input leaves log and next ID unchanged.
- Pruning keeps retained references/cutoff, never reuses IDs or resets chronology.
- Two worlds have separate logs; same appends give identical records.
- Full Debug and Release: PATH="$HOME/.dotnet:$PATH" dotnet test SimulationTests.

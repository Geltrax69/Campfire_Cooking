# P1-17: Per-NPC memory importance and decay

**Role:** Knowledge
**Branch:** task/P1-17-memory-decay
**Depends on:** P1-11 (merged)

## Goal
Store per-NPC memories of structured claims, reinforce them, decay/expire them
from approved memory rules, and retain any referenced truth events safely.

## Context
Read AGENTS.md and required startup documents, ARCHITECTURE sections 6 and 8,
docs/design/KNOWLEDGE.md section 2, and Content/social/social.json memory data.
False beliefs decay exactly like true ones; memory never reads world truth.

- SimulationTests/Knowledge/

## You must not edit
- Anything outside those folders. No Content/docs/configuration/dependencies,
  Unity, git writes or child agents.

## Requirements
1. C# 9/.NET Standard 2.1, tests first, no Unity/dependencies.
2. Load immutable MemoryRules from the `memory` object in approved social JSON
   using BCL serialization. Validate version, ordered 0..100 level coverage,
   IDs/ranges/positive retention days and the numeric decay values. Ignore other
   social sections. Leave stream ownership with the caller.
3. A memory belongs to one NPC and stores a structured BeliefClaim, explicit
   importance 0..100, formed time, last reinforced time, current strength and an
   optional valid origin WorldEventId. It does not assert the claim is true.
4. A per-NPC MemoryStore has deterministic claim order, explicit add/update and
   query. Re-experiencing/retelling a claim at a nondecreasing time refreshes its
   retention clock and accepts explicit new importance; never silently amplify.
5. Decay only on whole elapsed game days, with no double-decay on repeated ticks:
   Trivia/Minor lose approved points per day; Notable per approved 3-day period;
   Important per approved 10-day period. Major strength does not decay inside
   the prototype because approved content gives only a note, but its approved
   720-day retention still applies. Expire at zero strength or retention age.
6. Extend KnowledgeState so every registered NPC has beliefs and memories; expose
   memory lookup without weakening belief isolation. RetainedEventIds is the
   sorted distinct union of belief and live-memory origin references.
7. MemorySystem runs in Memory phase with supplied immutable rules and processes
   NPCs/claims deterministically. It does not create memories from events/beliefs,
   change relationships, generate rumors or decide importance.
8. Keep near 500 lines including tests; split loading/state if necessary.

## Tests required
- Load approved five levels/rates/retentions; malformed ranges/version rejected;

- Trivia/minor fades in days, Notable/Important at approved cadence, Major remains

- Whole-day boundaries, repeated same-minute ticks, refresh, backdated rejection,
  false-claim parity, per-NPC isolation and deterministic order.
- Retained IDs include live belief+memory refs and drop expired memory-only refs.
- Full Debug/Release suites and `git diff --check`.

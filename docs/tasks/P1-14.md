# P1-14: Stock counting and missing-stock inference

**Role:** Knowledge
**Branch:** task/P1-14-stock-inference
**Depends on:** P1-07, P1-12

## Goal
Let a shopkeeper compare an expected ledger count with an observed physical count,
record that count as truth, and form a belief about missing stock without naming a thief.

## Context
This is the no-witness heart of the Apple Test: Mira can know six apples are
missing at dusk, but the count alone cannot reveal who took them.

## Requirements
1. Accept an immutable, caller-supplied count snapshot containing owner, location,
   item, expected count and observed count; do not read Economy state directly.
2. Validate nonnegative counts and require an existing knowledge store for the counter.
3. Append one `StockCounted` truth event using only the existing event fields.
4. When observed is below expected, create/update the counter's inferred structured
   belief for the exact missing quantity, with caller-supplied confidence and event source.
5. Equal or surplus counts must not create a missing-stock belief.
6. Never name, rank or imply a thief; do not inspect theft events or other NPC beliefs.
7. Keep behavior atomic where validation can fail, deterministic and C# 9 compatible.

## Tests required
- Expected 20 and observed 14 records a count and yields “6 missing” for the counter only.
- The inferred claim has no actor and references the count event, not a theft event.
- Equal/surplus counts create no missing belief.
- Invalid counts, missing store and invalid confidence leave state unchanged.

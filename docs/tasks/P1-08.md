# P1-08: Atomic theft command and truth event

**Role:** Economy
**Branch:** task/P1-08-theft
**Depends on:** P1-04, P1-07

## Goal
Add a command that atomically moves requested items from an owned inventory to
the thief and records what actually happened as world truth, without moving money.

## Context
This is the player action at the centre of the Apple Test. Perception will later
decide who noticed the truth event; this task must not create beliefs or suspects.

## You may edit
- `Packages/com.geltrax.livingworld.simulation/Runtime/Economy/`
- `SimulationTests/Economy/`

## You must not edit
- Anything outside the folders above. If a Core API is insufficient, stop and report it.

## Requirements
1. Implement an immutable command compatible with the existing command queue.
2. Validate positive quantity, known item, distinct source/destination inventories,
   available stock, and destination eligibility before changing state.
3. A successful execution transfers the exact aggregate count atomically and appends
   one `Theft` world event with time, location, thief actor, item and quantity facts.
4. A rejected execution changes no inventory, wallet, or event log state.
5. Do not encode witness, suspicion, belief, ownership law, or game-specific apple logic.
6. Keep deterministic ordering and C# 9 compatibility; no Unity references.

## Tests required
- Successful theft lowers source stock, raises thief stock, records one truth event,
  and leaves all wallet balances unchanged.
- Insufficient/invalid requests are atomic and log no theft.
- Queued theft executes at the next command phase in FIFO order.

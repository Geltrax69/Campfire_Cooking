# P3-02: Recipe execution

**Role:** Economy agent
**Branch:** task/P3-02-recipe-execution
**Depends on:** P3-01

## Goal
Implement recipe execution from Content/recipes/recipes.json: cooking and crafting sessions that consume inputs, roll for failure, produce quality-scaled outputs, and respect level gates, fuel, time, and permission.

## Context
Phase 3 is "Skills, crafting and cooking". P3-01 built the skill state. This task builds the recipe system that uses it. Recipes are defined in Content/recipes/recipes.json (21 recipes: 13 cooking, 8 crafting). The design is in docs/design/RECIPES.md.

## Requirements
1. **RecipeDefinition**: Load from Content/recipes/recipes.json. Fields: id, name, category (cooking/crafting), skill (nullable SkillId), minLevel, difficulty (1-5), inputs (ItemTypeId → count), outputs (ItemTypeId → count, or repair spec), timeMinutes, location (nullable), tool, permission (nullable: npc + what), qualityRule formula, fermentDays (nullable).
2. **RecipeCatalog**: Loads all recipes from Content. Methods: `Get(recipeId)`, `GetBySkill(skillId)`, `GetByCategory(category)`.
3. **CanCook(actor, recipe, skillStore, inventory, location, relationships)**: Returns (bool canDo, string reason). Checks:
   - Skill level >= recipe.minLevel (hard gate)
   - Inventory has all inputs in sufficient quantity
   - Actor is at recipe.location (if specified)
   - Permission: if recipe.permission != null, the permitting NPC must be willing (for now: relationship trust >= 40, or the actor IS the permitting NPC; document this as a simplification)
   - Fuel: if recipe.tool == "campfire", inventory must have 1× item_firewood (consumed as part of inputs)
4. **Cook(recipe, actor, skillStore, inventory, day, rng)**: Executes the recipe:
   - Consume all inputs from inventory (including fuel)
   - Roll failure: `failChance = clamp((difficulty - skillLevel + 1) × 10, 0, 40)%`. Use rng.NextInt(100) < failChance.
   - On failure: inputs lost, no outputs, return failure result. (Waste: at skill levels 1-2, the design says ~30% waste; for simplicity, failure = 100% of inputs lost, success = 0% waste. Document this.)
   - On success: 
     - Quality = `clamp(average input quality + skill qualityBonus, 0, 100)`. Input quality defaults to 50 if not tracked. For recipe_master_stew, floor is 80.
     - Add outputs to inventory with the computed quality.
     - Grant skill practice: 1 point (or 2 if taught - caller handles teaching logic)
     - Handle fermentDays: if set, outputs are not immediately available (return a "fermenting" result with available day = day + fermentDays; P3-03 or later can implement the delayed delivery)
     - Handle repair outputs: restore tool condition (if tool condition is not yet implemented, log it and skip; document as future work)
   - Return a CookResult: Success/Failure, quality, outputs, practice points earned.
5. **Quality affects price**: When a cooked item is sold, sale price = `baseValue + round((quality - 50) / 25)`, minimum 1. (This may already exist in the price system; if so, wire it up. If not, document as P3-03 work.)
6. **Deterministic**: All randomness uses the provided rng (world's seeded RNG).

## Tests required
- `AtLevelRecipeSucceedsUsually`: Level 1 cook, difficulty 1 recipe → success rate ~90% over 100 trials (allow 80-95%).
- `TwoLevelsAboveFailsOften`: Level 1 cook, difficulty 3 recipe → failure rate ~30% over 100 trials (allow 20-40%).
- `FailureLosesInputs`: Failed recipe consumes inputs, produces no outputs.
- `QualityScalesWithSkill`: Same recipe, level 1 vs level 5 cook → higher quality from level 5.
- `LevelGateBlocks`: Level 1 cook cannot attempt minLevel 3 recipe.
- `MissingInputsBlocks`: Cannot cook without required ingredients.
- `MasterStewQualityFloor`: recipe_master_stew always quality >= 80.

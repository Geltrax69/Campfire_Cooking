# P6-01: Village LOD (level of detail)

**Role:** Core + Agents agent
**Branch:** task/P6-01-village-lod
**Depends on:** P5-04

## Goal
Implement neighboring villages as level-of-detail entities: Millbrook is fully simulated (LOD_FULL), neighboring villages are abstract (LOD_ABSTRACT) with population, wealth, food, and mood.

## Context
Phase 6 is "Expanded world". This task builds the foundation: multiple villages can exist, but only Millbrook gets the full NPC simulation. Others are abstract entities that tick at low fidelity.

## Requirements
1. **VillageId**: Strongly-typed ID for villages (e.g., `village_millbrook`, `village_kings_rest`).
2. **VillageLOD enum**: `Full` (Millbrook: full NPC simulation) and `Abstract` (others: stats only).
3. **AbstractVillageState**: For LOD_ABSTRACT villages:
   - VillageId, name, LOD level
   - Population (count), Wealth (copper), FoodSupply (0-100), Mood (0-100, like happiness)
   - Location (for travel time calculations)
   - These are simple values, updated by abstract rules (not full simulation).
4. **VillageRegistry**: Collection of all villages.
   - `Get(villageId)`, `GetAll()`, `GetByLOD(lod)`
   - Millbrook is always LOD_FULL; others are LOD_ABSTRACT.
   - `Capture()`/`Restore()` for persistence.
5. **WorldState integration**: Add `Villages` to WorldState.
6. **Abstract tick**: Each day, abstract villages update:
   - Population: small random drift (±1, seeded RNG)
   - Wealth: drift based on trade (P6-02 will wire this; for now, small random drift)
   - FoodSupply: seasonal drift (lower in winter, higher after harvest)
   - Mood: drift toward 50, affected by food supply
   - All deterministic (seeded RNG).
7. **Initial villages**: Create 2-3 neighboring villages:
   - `village_kings_rest` (large town, 2 days travel)
   - `village_oakhollow` (small hamlet, 1 day travel)
   - (Names from WORLD.md if available; otherwise use these and document.)
8. **Deterministic**: All drift uses seeded RNG.

## Tests required
- `VillagesRegister`: Create registry; verify Millbrook is Full, others are Abstract.
- `AbstractVillagesTick`: Tick 30 days; verify populations/wealth change (drift), stay in valid ranges.
- `LODLevels`: Verify GetByLOD returns correct villages.
- `CaptureRestoreRoundTrip`: Village registry survives save/load.

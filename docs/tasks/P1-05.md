# P1-05: Locations and timed NPC travel

**Role:** Core Simulation
**Branch:** task/P1-05-location-travel
**Depends on:** P1-02, merged in PR #2

## Goal
Look up travel duration between known locations and move an NPC only after
the required game minutes. Read approved content in tests; never rebalance it.

## Context
Read AGENTS.md, required docs, docs/design/LOCATIONS.md and Content/world/locations.json.
The JSON defines 23 locations and explicit, undirected travelMinutes links.
Use these integer links as authoritative (do not recalculate distances or invent
speed settings). Missing direct pairs can use shortest paths through the links.

## You may edit
- Packages/com.geltrax.livingworld.simulation/Runtime/Core/Locations/
- SimulationTests/Core/Locations/

## You must not edit
- Other folders, docs, Content, Assets, configuration or worktrees.
- No git writes, new dependencies or child agents.

## Requirements
1. Tests first, C# 9, namespace LivingWorld.Simulation.Core. Aim <=400 lines with
   tests; report if safe implementation needs a split rather than dropping tests.
2. Immutable location definitions include typed ID, name, type, integer x/y and
   optional NpcId owner (null = communal). Validate default IDs and blank strings.
3. Immutable LocationMap accepts definitions and undirected positive-minute links;
   rejects duplicates/unknown endpoints/self links. Defensive copies, stable ID
   enumeration. Precompute shortest travel durations, handling disconnected pairs
   and arithmetic overflow safely. Same known location takes zero minutes.
4. Add partial WorldState.InitializeTravel(LocationMap), exactly once, and a
   Travel state object holding map and NPC travel state (not full NPC behaviour).
   Register NPC IDs at existing locations; reject invalid/duplicate registrations.
5. Provide a StartTravel API using WorldState.Clock (not caller-supplied time).
   Capture arrival = Clock.Advance(duration) before changing state; reject
   unknown/unreachable destinations and already-travelling NPCs without mutation.
   Same-place travel is a no-op. In transit, NPC is not present at either endpoint;
   preserve origin, destination and arrival time explicitly for later perception.
6. TravelSystem : IWorldSystem, Id core.travel, Phase Actions; explicitly register
   it with World. At or after arrival minute, update NPC location in ordinal ID
   order. Use absolute arrival time so starting travel during a tick never gets a
   free minute. No per-tick sorting. No events dependency in this parallel part.
7. Runtime contains no JSON library or hardcoded village. Test-only System.Text.Json
   (part of net8) may read Content into the generic constructors. Find repository
   root from TestContext output path, not a developer-specific absolute path.
   A production content loader remains a later task, not claimed implemented here.

## Tests required
- Read all 23 real locations and links; check known forward/reverse routes, same
  location, indirect shortest route and an intentionally disconnected tiny map.
- NPC arrives only at correct minute (including nonzero start and in-tick start);
  several travellers, no presence while travelling, deterministic order/results.
- Invalid definitions/links, default IDs, duplicate NPC, already travelling,
  unknown destinations and time overflow leave state unchanged.
- Full suite Debug/Release using PATH="$HOME/.dotnet:$PATH" dotnet test SimulationTests.

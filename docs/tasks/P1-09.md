**Role:** Agents (NPC behaviour)

## Goal and context
Load the 20 approved NPC identities and numeric need rates into validated state;
advance awake needs without losing fractional per-minute changes. Read AGENTS.md,
startup docs, CHARACTERS.md and Content/npcs/npcs.json. No behaviour invented.

## Requirements
1. C#9, .NET Standard 2.1, tests first. No third-party or engine dependencies.
2. Immutable NpcDefinition: typed Id, name, age, gender, occupation, home/workplace,
   StartingMoneyCopper, immutable ordinal traits, NeedRates for hunger/energy/social.
   Starting money is a definition, not a second mutable wallet; economy owns wallets.
3. Production NpcContentLoader.Load(Stream, LocationMap) uses BCL
   DataContractJsonSerializer with required DTO members and simple dictionary format;
   no System.Text.Json runtime dependency. Validate version, 20 actual content rows,
   duplicates, unknown locations, required fields, ranges 0..100 for traits and
   nonnegative money/rates. Do not enforce exactly 20 for caller-provided tiny worlds.
   Loader returns definitions, sorted by ID, all-or-nothing and leaves input stream
   ownership with caller. Ignore unknown future fields rather than inventing semantics.
4. NpcState has definition and Needs. Initial hunger/energy/social are REQUIRED
   caller parameters (not invented default values). NeedState stores integer
   sixtieths internally: each awake minute adds hungerPerHour units and subtracts
   energyPerHour/socialPerHour units, clamps to 0..6000. Expose whole 0..100 values
   and remainder/state needed for eventual saves. Validate all input before mutation.
5. NpcRegistry registers unique NPCs, deterministic read-only iteration. Add
   WorldState.Npcs via NEW partial file inside your folder, Core namespace only
   for that seam. NeedsSystem ticks registry in Needs phase; awake needs only.
   An explicit sleeping flag may pause awake drain; sleep recovery and starting
   need defaults are NOT specified in approved data and must be reported, not guessed.
6. Keep definitions/loading, then mutable state/needs as separate file groups so
   orchestrator can split into <=500-line PRs. Aim minimal complete implementation;
   report line count and groups if exceeding ~400 lines with tests.

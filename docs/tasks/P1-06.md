## Requirements
1. C# 9, .NET Standard 2.1 compatible, tests first, no dependencies/Unity.
2. ItemDefinition immutable: ItemTypeId Id, Name, Category, integer BaseValue,
   phase, optional hunger/health/social integer effects. Validate IDs, strings,
   nonnegative prices and phase. ItemCatalog defensive copies, duplicate rejection,
   ordinal iteration, typed lookup; only supported phases are selected by caller.
3. Inventory(catalog), Count(item), Add(item,quantity), TryRemove(item,quantity),
   TransferTo(destination,item,quantity): positive mutations only, checked overflow,
   no negative stock, no silent clamping or partial transfers. Unknown/default IDs
   rejected. Destination overflow/failure leaves both inventories unchanged.
   Self-transfer must not create or destroy items. Enumeration is stable/read-only.
4. Money stays in integer copper wallets (P1-07); do not invent an item_coin since
   approved currency has coin_* IDs separate from item types. No stack-size cap on
   bulk stock: the catalog stack is a UI grouping, not shop capacity.
5. Keep within ~400 lines including tests if feasible; report safe split if larger.
   Runtime JSON loading not required for this task. Test-only System.Text.Json can
   verify all approved Phase 1 items using repository-relative discovery.

## Tests required
Catalog validation/order/immutable copies; real Phase 1 apples, bread and ale;
add/remove/insufficient/unknown IDs; overflow and atomic transfers; independent
inventories, invariant total count across transfers. Debug and Release full suites

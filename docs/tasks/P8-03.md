# P8-03: Dialogue contract (enforcement: dialogue never changes state)

**Role:** Knowledge agent
**Branch:** task/P8-03-contract
**Depends on:** P8-02

## Goal
Build the `DialogueSession` — the single read-only entry point for talking to an
NPC — and prove by construction and by test that dialogue can never change game
state or leak secrets.

## Context
P8-01 built the FactSheet (only NPC-known facts). P8-02 built the template
phrasing engine. This task wraps them in a `DialogueSession` that enforces the
core Phase 8 rule from the approved design: **dialogue may phrase facts only; it
cannot reveal unknown facts or change game state.**

The session is the contract a future AI adapter would also implement: it takes a
fact sheet + phrasing engine and produces utterances, with no path back into
mutable world state.

## Requirements
1. **`DialogueSession`** (`Runtime/Knowledge/DialogueSession.cs`):
   - Constructor: `(FactSheet sheet, IPhrasingEngine engine)`.
   - `string Say(DialogueIntent intent)` — returns the phrased utterance.
   - Holds only the sheet and engine — **no reference to WorldState**.
     This is enforcement by construction: the session physically cannot reach
     mutable state.
   - Document the contract in the class remarks: what dialogue may and may not do.
2. **Secret-leakage guard**:
   - Define what counts as a secret for this purpose: any world-truth fact not
     present in the sheet (e.g., another NPC's wallet balance, an unperceived
     event, a belief the NPC doesn't hold).
   - Test: build a session for an NPC, run all intents, assert no secret strings
     (wallet amounts, unperceived event details, other NPCs' private beliefs)
     appear in any output. Use distinctive sentinel values to make the test robust.
3. **Read-only API proof**:
   - Test: `DialogueSession` exposes no WorldState reference (reflection check
     that no field/property of the session's types references WorldState or any
     mutable store). This locks the design against future regressions.
   - Test: running 100 utterances across NPCs leaves the world digest unchanged.
4. **Deceased / unknown NPC handling**: `Say` on a sheet for a deceased NPC or a
   placeholder (unknown) sheet must not throw; document the behavior (e.g.,
   deceased NPCs can't be talked to — the builder degrades gracefully, and the
   session phrases what's there).
5. **Session determinism**: same sheet + engine + intent → same utterance
   (inherited from P8-02, but assert at the session level).

## Tests required
